【4. 修复 13 项产品缺陷（含 3 项 P0 阻断级）】
  ★ P0-1 文档入库 100% 失败（最严重）
     现象：任何文档上传后必失败，报 kb_vectors.chunk_id 非空约束被违反
     根因：Tortoise ORM 0.21.7 + MySQL 下 bulk_create 不回填自增主键
          （仅 PostgreSQL 支持 RETURNING），导致向量 chunk_id=NULL、
           子块 parent_id=NULL
     修复：新增 _fetch_ids() 按 doc_id+is_parent+seq 回查真实主键并校验条数
     影响：这是知识库产品最核心功能，此前完全不可用

  ★ P0-2 整条检索链路崩溃
     现象：检索测试/问答/Agent 全部 500
     根因：retriever._backfill_stage 用了 strategy.candidate_limit，
          但函数签名未接收 strategy → NameError
     修复：签名补 strategy 参数 + 调用点补传

  ★ P0-3 Mock 沙箱 SSE 响应永久挂起
     现象：astream 调用永久阻塞，脚本被强杀
     根因：声明 protocol_version="HTTP/1.1"，但 SSE 响应既无
          Content-Length 也无 Transfer-Encoding，客户端等不到响应结束
     修复：改分块传输编码（chunked）

  ☆ P1 级（共 9 项，详见《测试报告.md》第四节）
     - Agent 自查节点从未真正执行（NameError 被 except 静默吞掉）
     - 工具/Prompt 模糊查询 500（QuerySet|QuerySet 不被 Tortoise 支持）
     - 脏工具配置拖垮整条问答/Agent 链路（Unsupported function {}）
     - Agent 图无限循环（GraphRecursionError: 25）
     - Agent 时间线 seq 全为 [1,1,1,1]（LangGraph state 副本问题）
     - 自查失败后无限重试
     - SSE 异常时 agent_run 卡 running 且错误消息为空
     - 并发上传后台任务被 GC 回收（文档永久卡 parsing）
     - 片段人工修正被静默还原（用户编辑数据丢失）

  ☆ P2 级（1 项）

## 📌 关键技术备忘（本轮踩坑总结，改造代码时注意）

  1. Tortoise ORM + MySQL：bulk_create 不回填自增主键，批量插入后需用主键
     建关联的场景必须回查（rag/ingest.py::_fetch_ids）
  2. asyncio 后台任务必须保存强引用，否则事件循环只持弱引用，任务被 GC 回收
  3. 保存内容后要重新向量化，必须「先落库再 reembed」，否则编辑会被旧值覆盖
  4. HTTP/1.1 的 SSE 响应必须有 Transfer-Encoding: chunked
  5. LangGraph 节点拿到的是 state 副本，节点内改动不回流 → 需从库中取真实值
  6. 测试 SSE 必须用增量解码，逐字节 decode 会撕裂中文
  7. 测试轮询文档状态必须等「全部进入终态」，parsing 不算收敛
